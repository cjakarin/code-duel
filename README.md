# Code Duel v2.3 — ระบบประลองการเขียนโปรแกรมเชิงแข่งขันแบบเรียลไทม์

รองรับ Python 3 และ C++17 · ผู้ดูแลตั้งโจทย์และดูโค้ดของผู้เล่นแบบสด · Console โต้ตอบได้ · ตรวจคำตอบอัตโนมัติ
**v2: โค้ดของผู้เล่นทุกครั้งรันในคอนเทนเนอร์ Docker ที่แยกจากเครื่องเซิร์ฟเวอร์**

## ติดตั้งและรัน (v2)

เครื่องเซิร์ฟเวอร์ต้องมี **Node.js 22+** และ **Docker** (Mac/Windows: Docker Desktop, Linux: Docker Engine)
ไม่ต้องติดตั้ง Python หรือ g++ บนเครื่องแล้ว เพราะอยู่ใน image ของ Docker

ทำครั้งแรกครั้งเดียว (ต้องใช้อินเทอร์เน็ต):

```bash
npm install
npm run build-runner      # สร้าง image code-duel-runner:2 (Python 3.12 + g++) ใช้เวลาสักครู่
npm run check             # ตรวจว่า Docker และ image พร้อม
```

ทุกครั้งที่ใช้งาน: เปิด Docker Desktop ให้ทำงานก่อน แล้ว

```bash
npm start
```

บรรทัดแรกต้องขึ้น `Code Duel v2.3.0 พร้อมใช้งาน` และบรรทัด "ที่รันโค้ด" ต้องขึ้น `Docker ...`
ถ้า Docker ไม่ทำงานหรือยังไม่มี image ระบบจะไม่เริ่ม และบอกวิธีแก้

> อัปเดตจาก v1: แตกไฟล์ใหม่ แล้วคัดลอกโฟลเดอร์ `data` จากของเดิมมาไว้ เพื่อเก็บคลังโจทย์

- หน้าผู้เล่น: http://<IP-เซิร์ฟเวอร์>:3000/player.html
- หน้าผู้ดูแล: http://<IP-เซิร์ฟเวอร์>:3000/admin.html (รหัสผ่านเริ่มต้น `admin1234`)

## เล่นในวงแลน

ตอนเปิดเซิร์ฟเวอร์ หน้าจอ terminal จะแสดงที่อยู่ให้เครื่องอื่นเข้า เช่น

```
วงแลน (Wi-Fi) : ผู้เล่นเข้า http://192.168.1.25:3000/player.html
```

หน้า admin ก็แสดงที่อยู่นี้ด้านบน พร้อมปุ่มคัดลอก ให้เครื่องผู้เล่นเปิดที่อยู่นี้ **ห้ามใช้ `localhost`** บนเครื่องผู้เล่น เพราะ `localhost` หมายถึงเครื่องของผู้เล่นเอง

ไลบรารีทั้งหมด (ตัวเขียนโค้ด, ตัวแสดง Markdown) ให้บริการจากเครื่องเซิร์ฟเวอร์เอง จึงใช้ในวงแลนที่ไม่มีอินเทอร์เน็ตได้ (ถ้าไม่มีเน็ต ฟอนต์จะเปลี่ยนเป็นฟอนต์ของเครื่องแทน)

### ถ้าเครื่องอื่นยังเข้าไม่ได้ ตรวจตามลำดับนี้

1. **ทดสอบบนเครื่องเซิร์ฟเวอร์ก่อน** ว่าเปิด `http://<IP-ที่แสดง>:3000/player.html` ได้ ถ้าเครื่องตัวเองยังเปิดผ่าน IP ไม่ได้ แปลว่าเซิร์ฟเวอร์ยังไม่ได้รันหรือ IP ผิด
2. **ไฟร์วอลล์ (สาเหตุที่พบบ่อยที่สุด)**
   - **Windows**: ตอนรันครั้งแรกถ้ามีหน้าต่าง Windows Security ขึ้นมา ให้ติ๊ก **Private networks** แล้วกด Allow ถ้าเผลอกด Cancel ไปแล้ว ให้เปิด PowerShell แบบ Run as administrator แล้วรัน
     ```powershell
     New-NetFirewallRule -DisplayName "Code Duel" -Direction Inbound -Protocol TCP -LocalPort 3000 -Action Allow -Profile Any
     ```
     และตรวจว่าเครือข่ายตั้งเป็น **Private** ไม่ใช่ Public (Settings → Network & Internet → คุณสมบัติของ Wi-Fi/Ethernet)
   - **macOS**: System Settings → Network → Firewall → Options → อนุญาต `node`
   - **Linux (ufw)**: `sudo ufw allow 3000/tcp`
3. **อยู่วงเดียวกันจริงไหม** IP สามตัวแรกควรเหมือนกัน เช่น `192.168.1.x` ทั้งหมด ลองสั่ง `ping <IP-เซิร์ฟเวอร์>` จากเครื่องผู้เล่น
4. **Wi-Fi แบบแยกเครื่อง** Wi-Fi สำหรับแขก (Guest) หรือ Wi-Fi ที่เปิด AP/Client Isolation จะห้ามเครื่องคุยกันเอง ให้ใช้ Wi-Fi หลักหรือสายแลน หรือปิด isolation ที่เราเตอร์
5. **มีหลาย IP** ถ้าเครื่องมี VPN, VirtualBox, Docker จะเห็นหลาย IP ให้ใช้ IP ของการ์ด Wi-Fi/Ethernet ที่ต่อวงเดียวกับผู้เล่น
6. **รันใน WSL2 (Windows)** WSL2 มีวงเครือข่ายแยก ให้รันด้วย Node.js บน Windows โดยตรง หรือทำ port proxy (PowerShell แบบ administrator):
   ```powershell
   netsh interface portproxy add v4tov4 listenport=3000 listenaddress=0.0.0.0 connectport=3000 connectaddress=<IP-ของ-WSL>
   ```
   (ดู IP ของ WSL ด้วยคำสั่ง `hostname -I` ใน WSL) แล้วเปิดไฟร์วอลล์ตามข้อ 2

## รูปแบบโจทย์ (Markdown)

ผู้ดูแลเขียนโจทย์ทั้งหมดเป็น Markdown ในหน้า admin โดยมีจอแสดงตัวอย่างหน้าผู้เล่นอยู่ข้าง ๆ แท็กที่ใช้ได้มีดังนี้

| แท็ก | ผู้เล่นเห็นไหม | ใช้ทำอะไร |
|---|---|---|
| `# ชื่อโจทย์` | เห็น | หัวข้อแรกคือชื่อโจทย์ |
| `## ...` และข้อความทั่วไป | เห็น | คำอธิบาย ข้อมูลนำเข้า ข้อมูลส่งออก (ใช้ Markdown ได้เต็มที่ เช่น ตาราง โค้ด รายการ) |
| `<example>` | เห็น | ตัวอย่าง แสดงเป็นกล่องข้อมูลนำเข้า/ส่งออก พร้อมปุ่ม "รันตัวอย่างนี้" |
| `<test>` | **ไม่เห็น** | เทสเคสลับ ใช้ตรวจตอนกด "ส่งคำตอบ" ใส่ได้หลายชุด |
| `<timelimit>2</timelimit>` | ไม่เห็นแท็ก | เวลาสูงสุดต่อเทสเคส (วินาที) ค่าเริ่มต้น 2 |
| `<!-- ... -->` | ไม่เห็น | หมายเหตุสำหรับผู้ดูแล |

```markdown
# ผลรวมสองจำนวน

กำหนดจำนวนเต็ม a และ b ให้หาผลรวม

## ข้อมูลนำเข้า
บรรทัดเดียว มีจำนวนเต็ม a และ b

## ข้อมูลส่งออก
ผลรวม a + b

## ตัวอย่าง
<example>
<input>
1 2
</input>
<output>
3
</output>
</example>

<timelimit>2</timelimit>

<test>
<input>
100 200
</input>
<output>
300
</output>
</test>
```

### สูตรคณิตศาสตร์

เขียนสูตรด้วยรูปแบบ LaTeX แล้วระบบแสดงเป็นสูตรที่อ่านง่าย (ใช้ KaTeX ทำงานแบบออฟไลน์ได้)

| เขียน | ผลลัพธ์ |
|---|---|
| `$1 \le n \le 10^5$` | สูตรในบรรทัด |
| `$a_1, a_2, \ldots, a_n$` | ตัวห้อย |
| `$$\sum_{i=1}^{n} a_i \bmod (10^9+7)$$` | สูตรแยกบรรทัด กึ่งกลาง |
| `\$5` | เครื่องหมายดอลลาร์ธรรมดา (ไม่เป็นสูตร) |

ไม่แปลงสูตรในโค้ด (`` `...` `` และ ```` ``` ````) และในกล่องตัวอย่าง ถ้าเขียนสูตรผิด จะแสดงเป็นตัวอักษรสีแดงแทน ไม่ทำให้หน้าพัง

เทสเคสลับถูกตัดออกที่ฝั่งเซิร์ฟเวอร์ก่อนส่งให้ผู้เล่น จึงไม่มีทางเปิดดูผ่านเบราว์เซอร์ได้
การตรวจคำตอบไม่สนใจช่องว่างท้ายบรรทัดและบรรทัดว่างท้ายไฟล์

## จัดหน้าจอผู้เล่น

หน้าผู้เล่นแบ่งเป็นสามส่วน โจทย์ (ซ้าย) ตัวเขียนโค้ด (ขวาบน) และ console (ขวาล่าง) แต่ละส่วนมีปุ่มที่หัวส่วนนั้น

- **◂ ซ่อนโจทย์** (ปุ่มซ้ายสุดของแถบเครื่องมือโค้ด หรือกด Ctrl+B / ⌘+B): ยุบโจทย์ไปเป็นแถบแคบทางซ้าย ให้ที่เขียนโค้ดกว้างเกือบเต็มจอ กดอีกครั้งเพื่อแสดงโจทย์
- **ยุบ**: ซ่อนส่วนนั้น โจทย์จะเหลือเป็นแถบแคบด้านซ้าย (กด "▸ โจทย์" เพื่อเปิดคืน) console จะเหลือแค่แถบหัว (คลิกเพื่อเปิดคืน)
- **ขยาย**: ให้ส่วนนั้นเต็มหน้าจอ กดอีกครั้ง (ปุ่มเปลี่ยนเป็น "คืนค่า") เพื่อกลับเลย์เอาต์ปกติ
- **ลากเส้นแบ่ง** ระหว่างโจทย์กับโค้ด หรือระหว่างโค้ดกับ console เพื่อปรับขนาด ดับเบิลคลิกเส้นแบ่งเพื่อคืนขนาดเดิม
- เมื่อกดรันโค้ดหรือส่งคำตอบ console จะเปิดขึ้นเองถ้ายุบอยู่ จะได้เห็นผลทันที
- เบราว์เซอร์จำการจัดหน้าจอไว้ รีเฟรชหน้าแล้วยังเป็นแบบเดิม

## หน้าผู้ดูแล

หน้า admin เลื่อนขึ้นลงได้ทั้งหน้า แถบควบคุมด้านบน (จำนวนผู้เล่น เวลา เริ่ม/จบ) ติดอยู่ด้านบนเสมอ ส่วนตั้งโจทย์อยู่ด้านบน จอของผู้เล่นอยู่ด้านล่าง

- ปุ่ม "ดูจอผู้เล่น ▾" มุมขวาล่าง พาเลื่อนลงไปที่จอผู้เล่นทันที (เมื่ออยู่ด้านล่างจะเปลี่ยนเป็น "ขึ้นไปตั้งโจทย์ ▴")
- ผู้เล่นแถวเดียว (1–2 คน หรือพอดีหนึ่งแถว): จอผู้เล่นสูงเต็มหน้าจอ
- ผู้เล่นหลายแถว: แต่ละแถวสูงประมาณ 2 ใน 3 ของจอ เลื่อนลงเพื่อดูแถวถัดไป

## คลังโจทย์

ด้านซ้ายของส่วนตั้งโจทย์ในหน้า admin คือคลังโจทย์

- **บันทึกเข้าคลัง / บันทึกลงคลัง**: เก็บโจทย์ที่กำลังเขียน (ถ้าเปิดมาจากคลังจะบันทึกทับข้อเดิม)
- **บันทึกเป็นโจทย์ใหม่**: ทำสำเนาเป็นอีกข้อ เหมาะกับการดัดแปลงจากโจทย์เดิม
- **กดชื่อโจทย์ในรายการ**: เปิดมาแก้ไข (ถ้ามีการแก้ที่ยังไม่บันทึก ระบบจะถามก่อน)
- **ค้นหา / ลบ / โจทย์ใหม่**
- **นำเข้า .md**: เลือกได้หลายไฟล์พร้อมกัน แต่ละไฟล์กลายเป็นโจทย์หนึ่งข้อ
- **ดาวน์โหลด .md**: เก็บโจทย์ที่กำลังแก้เป็นไฟล์ไว้สำรองหรือแบ่งปัน
- โจทย์ที่เผยแพร่อยู่จะมีป้าย "กำลังใช้" ในรายการ

การเก็บข้อมูล:

- โจทย์แต่ละข้อเป็นไฟล์ `data/problems/<id>.md` สำรองข้อมูลได้ด้วยการคัดลอกโฟลเดอร์ `data`
- โจทย์ที่เผยแพร่ล่าสุดเก็บไว้ใน `data/current.json` รีสตาร์ตเซิร์ฟเวอร์แล้วโจทย์ยังอยู่
- ครั้งแรกที่เปิดเซิร์ฟเวอร์ ระบบจะใส่โจทย์ตัวอย่าง "ผลรวมสองจำนวน" ไว้ในคลังให้หนึ่งข้อ
- ไฟล์ในคลังมีเทสเคสลับอยู่ด้วย อย่าแชร์โฟลเดอร์ `data` ให้ผู้เล่น

## ผลการตรวจ

- ผ่าน / คำตอบผิด / เกินเวลา / รันไม่สำเร็จ / ผลลัพธ์ยาวเกินไป / คอมไพล์ไม่ผ่าน
- ผู้เล่นเห็นผลเป็นรายเทสเคส แต่ไม่เห็นข้อมูลของเทสเคส
- คะแนนนับจากการส่งที่ดีที่สุด คนแรกที่ผ่านครบทุกชุดได้ป้าย 🏆 ผู้ชนะ (การแข่งยังไม่จบอัตโนมัติ ผู้ดูแลกดจบเอง)
- การเผยแพร่โจทย์ใหม่หรือกดเริ่ม/รีเซ็ตการแข่ง จะล้างคะแนนของผู้เล่นทุกคน

## ผู้เข้าแข่งขัน รหัสเข้าใช้ และรอบการแข่ง (v2.1)

### รหัสเข้าใช้

- ผู้ดูแลกำหนดจำนวนผู้เข้าแข่งขันที่ช่อง "ผู้เข้าแข่งขัน [ ] คน" → กด "ปรับ" ระบบสร้าง **รหัสเข้าใช้ 6 ตัวอักษร** (เช่น `K7P-3MX`) ให้แต่ละคนอัตโนมัติ ไม่ใช้ตัวที่สับสนง่าย (O/0, I/1)
- เปิดแผง "ผู้เข้าแข่งขันและรหัสเข้าใช้" ในหน้า admin เพื่อ
  - ตั้งชื่อล่วงหน้า (ถ้าเว้นว่าง ผู้เข้าแข่งขันกรอกชื่อเองตอนเข้าครั้งแรก)
  - ดูสถานะออนไลน์
  - "สร้างรหัสใหม่" ให้คนที่ทำรหัสหาย (รหัสเดิมใช้ไม่ได้ทันที)
  - **🖨 พิมพ์บัตรรหัส** (หน้าละหลายใบ ตัดแจกได้) หรือ **ดาวน์โหลด CSV**
- ผู้เข้าแข่งขันเปิดหน้า player → ใส่รหัส → เข้าใช้ได้ทันที หลุดแล้วกลับมาด้วยรหัสเดิม โค้ดยังอยู่
- รหัสหนึ่งใช้ได้ทีละเครื่อง ถ้ามีคนใช้อยู่ เครื่องที่สองจะเข้าไม่ได้
- ใส่รหัสผิด 5 ครั้งติดกัน ต้องรอ 1 นาที (กันการเดารหัส)

### รอบการแข่ง

1. เลือก/เผยแพร่โจทย์ → ตั้งเวลา → กด **"เริ่มรอบที่ N"** (โจทย์เปิดให้ทุกคนพร้อมกัน)
2. หมดเวลา หรือกด **"จบรอบ"** → ระบบบันทึกผลทันที และผู้เข้าแข่งขันทุกคนเห็นหน้าต่าง "สรุปผลรอบที่ N" พร้อมอันดับของตัวเอง
3. กด **"เตรียมรอบถัดไป"** → ซ่อนโจทย์ ล้างโค้ด → เผยแพร่โจทย์ข้อถัดไป → เริ่มรอบใหม่

การเรียงอันดับในแต่ละรอบ: ผ่านเทสเคสมากกว่า → ทำคะแนนนั้นได้เร็วกว่า (นับจากเริ่มรอบ) → ส่งน้อยครั้งกว่า
คะแนนรอบ = ร้อยละของเทสเคสที่ผ่าน (ผ่านครบ = 100) และอันดับรวม = ผลรวมคะแนนทุกรอบ ถ้าเท่ากันดูเวลารวมที่น้อยกว่า

### สรุปผล (ปุ่ม 📊 สรุปผล)

- **อันดับรวมทุกรอบ** และ **ผลแต่ละรอบ** (คะแนน เวลา จำนวนครั้งที่ส่ง ภาษา และโค้ดสุดท้ายของแต่ละคน)
- **โหมดนำเสนอ** ตัวใหญ่ ซ่อนโค้ด สำหรับฉายประกาศผล
- **CSV ผลรวม / CSV รายละเอียด** เปิดใน Excel ได้ (ภาษาไทยไม่เพี้ยน) และ **พิมพ์ / PDF**
- **ลบรอบนี้** สำหรับรอบทดสอบ
- **เริ่มงานแข่งใหม่** เก็บงานเดิมไว้ใน `data/events/` แล้วเริ่มนับรอบใหม่ เลือกได้ว่าจะใช้รายชื่อและรหัสชุดเดิมหรือสร้างใหม่

ผลทุกรอบ รายชื่อ และรหัสเข้าใช้ บันทึกใน `data/event.json` ทันที รีสตาร์ตเซิร์ฟเวอร์แล้วไม่หาย

## ลำดับการใช้งาน

1. ผู้ดูแลเข้าหน้า admin → กำหนดจำนวนผู้เข้าแข่งขัน → (ถ้าต้องการ) ใส่ชื่อ → พิมพ์บัตรรหัสแจก
2. ผู้เข้าแข่งขันเปิดหน้า player ด้วยที่อยู่ที่แสดงในหน้า admin → ใส่รหัสเข้าใช้
3. ผู้ดูแลเลือกโจทย์จากคลัง หรือเขียนใหม่ด้วย Markdown → กด "เผยแพร่โจทย์"
   - ก่อนเริ่มรอบ ผู้เข้าแข่งขันเห็นข้อความ "โจทย์ยังไม่เปิด" (เซิร์ฟเวอร์ไม่ส่งเนื้อหาโจทย์ไปเลย) พิมพ์โค้ดเตรียมไว้ได้แต่รันไม่ได้
4. ตั้งเวลา → "เริ่มรอบที่ N" → ระหว่างแข่ง ผู้ดูแลเห็นโค้ด console และอันดับสดของทุกคน กด "ดูเต็มจอ" เพื่อขยายจอของคนที่ต้องการ (Esc เพื่อออก)
5. ผู้เข้าแข่งขันกด "รันโค้ด" (Ctrl+Enter) เพื่อทดสอบ และ "ส่งคำตอบ" (Ctrl+Shift+Enter) เพื่อตรวจกับเทสเคสลับ
6. จบรอบ → ทุกคนเห็นสรุปผลรอบ → "เตรียมรอบถัดไป" → วนข้อ 3
7. จบงาน → เปิด "📊 สรุปผล" เพื่อประกาศผล ดาวน์โหลด CSV หรือพิมพ์

## การแยกสภาพแวดล้อมด้วย Docker (v2)

ทุกครั้งที่ผู้เล่นกด "รันโค้ด" หรือ "ส่งคำตอบ" ระบบสร้างคอนเทนเนอร์ใหม่ขึ้นมาหนึ่งตัว ใช้เสร็จแล้วลบทิ้งทันที คอนเทนเนอร์มีข้อจำกัดดังนี้

| ข้อจำกัด | ป้องกันอะไร |
|---|---|
| ไม่มีเครือข่าย (`--network none`) | โค้ดผู้เล่นออกอินเทอร์เน็ต หรือเจาะเครื่องอื่นในวงแลนไม่ได้ |
| ไม่เห็นไฟล์ของเครื่องเซิร์ฟเวอร์ | อ่านเทสเคสลับ คลังโจทย์ หรือไฟล์ส่วนตัวไม่ได้ |
| ระบบไฟล์อ่านอย่างเดียว เขียนได้เฉพาะ `/work` และ `/tmp` ขนาดจำกัด | ทำลาย image หรือเขียนไฟล์จนดิสก์เต็มไม่ได้ |
| จำกัด RAM 256 MB, CPU 1 ตัว, 64 โปรเซส | กันโค้ดกินทรัพยากรจนเครื่องค้าง กัน fork bomb |
| ผู้ใช้ไม่ใช่ root, ตัดสิทธิ์พิเศษทั้งหมด (`--cap-drop ALL`, `no-new-privileges`) | ลดโอกาสหลุดออกจากคอนเทนเนอร์ |
| จำกัดเวลาด้วย `timeout` ภายในคอนเทนเนอร์ และคอนเทนเนอร์หมดอายุเองใน 30 นาที | ไม่มีโปรเซสค้าง แม้เซิร์ฟเวอร์ล่มกลางคัน |

เพิ่มเติม:

- ผลตรวจใหม่: **หน่วยความจำเกิน** (เมื่อโปรแกรมถูกฆ่าเพราะใช้ RAM เกิน `RUNNER_MEMORY`)
- เวลาที่แสดงในผลตรวจรวมเวลาเริ่มคำสั่งใน Docker ราว 50–150 ms ต่อเทสเคส การตัดสิน "เกินเวลา" ใช้ตัวจับเวลาภายในคอนเทนเนอร์
- การรันแต่ละครั้งช้าลงราว 0.5–1 วินาที เพราะต้องสร้างคอนเทนเนอร์ (จะเห็นข้อความ "🐳 กำลังเตรียมคอนเทนเนอร์")
- ปิดเซิร์ฟเวอร์ด้วย Ctrl+C ระบบจะลบคอนเทนเนอร์ที่ค้างให้ เปิดครั้งถัดไปก็ลบของที่ค้างจากครั้งก่อนให้เช่นกัน
- C++ ใช้ g++ ของ GNU ใน image เหมือนกันทุกเครื่อง จึงใช้ `#include <bits/stdc++.h>` ได้แม้เซิร์ฟเวอร์เป็น Mac
- หน้า admin แสดงป้าย "🐳 รันใน Docker" หรือ "⚠ รันบนเครื่องโดยตรง" ที่แถบด้านบน

ข้อจำกัดที่ควรรู้: Docker ลดความเสี่ยงได้มาก แต่ไม่ใช่การป้องกันสมบูรณ์ ถ้าเปิดให้คนทั่วไปเข้าผ่านอินเทอร์เน็ต ควรรันเซิร์ฟเวอร์บนเครื่องที่ไม่มีข้อมูลสำคัญ อัปเดต Docker และ Node.js สม่ำเสมอ และพิจารณาใช้ gVisor (`--runtime runsc`) หรือ VM แยก

## จอผู้ชม (v2.3)

มีสองลิงก์ ดูได้จากแผง **"จอผู้ชม"** ในหน้า admin (มีปุ่มคัดลอกและเปิด)

| | 📊 ตารางคะแนน `/scoreboard.html` | 🎥 จอผู้ชม `/spectator.html?key=…` |
|---|---|---|
| ใครดู | ทุกคน (ผู้เข้าแข่งขันก็เปิดได้ มีลิงก์ในหน้า player) | จอฉาย ห้องผู้ชม การถ่ายทอดสด |
| เนื้อหา | อันดับสด แถบเทสเคสที่ผ่าน ข่าวด่วน First Blood นับถอยหลัง | ทุกอย่างทางซ้าย + จอโค้ด 4 อันดับแรก หรือ Spotlight คนเดียว |
| โค้ด | ไม่มีเลย | ตามที่ตั้ง: ซ่อน / หน่วงเวลา / สด |
| เข้าถึง | ไม่ต้องใช้รหัส | ต้องมีคีย์ในลิงก์ ("สร้างคีย์ใหม่" แล้วลิงก์เดิมใช้ไม่ได้ทันที) |

ทั้งสองหน้าไม่ได้รับเทสเคสลับหรือรหัสเข้าใช้เลย

### การตั้งค่า (แผง "จอผู้ชม" ในหน้า admin)

- **โค้ดบนจอผู้ชม**
  - *ซ่อนระหว่างแข่ง* (ค่าเริ่มต้น): ใช้เมื่อจอฉายอยู่ห้องเดียวกับผู้เข้าแข่งขัน จอแสดงสถานะแทน เช่น "กำลังพิมพ์" "กำลังทดสอบโค้ด" "กำลังคิด" และจำนวนบรรทัด
  - *หน่วงเวลา*: แสดงโค้ดช้ากว่าจริง N นาที ผู้ชมยังตามได้ แต่ผู้เข้าแข่งขันนำไปใช้ไม่ทัน
  - *สด*: ผู้ชมอยู่คนละห้อง หรือถ่ายทอดสดออกไปข้างนอก
  - จบรอบแล้ว ทุกโหมดแสดงโค้ดสุดท้ายได้
- **แช่แข็งตาราง N นาทีสุดท้าย** (ค่าเริ่มต้น 10, ใส่ 0 = ไม่แช่แข็ง): ตารางบนจอหยุดอัปเดต การส่งหลังจากนั้นแสดงเป็น `+N?` ข่าวด่วนบอกแค่ "ส่งคำตอบ (ผลถูกซ่อน)"
- **นับถอยหลัง 3-2-1** ก่อนเปิดโจทย์ (ทุกจอพร้อมกัน ตั้งเวลาตามนาฬิกาเซิร์ฟเวอร์)
- **Spotlight**: เลือกคนเดียวขึ้นเต็มจอผู้ชม หรือกดปุ่ม 🎥 บนการ์ดของคนนั้น กดซ้ำเพื่อกลับเป็น 4 อันดับแรก

### ประกาศผลแบบลุ้น

ถ้าตารางถูกแช่แข็งตอนจบรอบ:

1. ผู้เข้าแข่งขันเห็นเฉพาะผลของตัวเอง (ผ่านกี่ชุด) ยังไม่รู้อันดับ
2. แผง "จอผู้ชม" เปิดเองพร้อมปุ่ม **"▶ เปิดผลคนถัดไป"**
3. กดทีละครั้ง ระบบเปิดผลจริงของคนทีละคน **จากอันดับล่างขึ้นบน** แถวนั้นกระพริบและเลื่อนไปอันดับใหม่บนจอ
4. เปิดครบ → ป้าย 🏆 ชนะเลิศ ขึ้นจอ ผู้เข้าแข่งขันทุกคนเห็นสรุปอันดับเต็ม

ผู้ดูแลเห็นผลจริงตลอดเวลาในหน้า admin

### ข่าวด่วนและเสียง

ข่าวด่วนแจ้งอัตโนมัติ: เริ่มรอบ, ส่งคำตอบ (ผ่านกี่ชุด), ✅ ผ่านครบ, 🩸 First Blood (ขึ้นป้ายใหญ่กลางจอ), 👑 ขึ้นนำ, ⏰ เหลือ 5 และ 1 นาที, 🧊 แช่แข็ง, 🏁 หมดเวลา

เสียงสร้างในเบราว์เซอร์ ไม่ต้องมีไฟล์ จอผู้ชมต้องกดปุ่ม **"🔇 เปิดเสียง"** หนึ่งครั้ง (ข้อกำหนดของเบราว์เซอร์) หน้า player มีปุ่ม 🔊/🔇 ให้ผู้เข้าแข่งขันปิดเสียงเองได้

## เครื่องมือสำหรับผู้ดูแลและครู (v2.2)

### ▶ Replay: ย้อนดูการพิมพ์โค้ด

ระหว่างแต่ละรอบ ระบบบันทึกทุกการเปลี่ยนแปลงของโค้ดผู้เข้าแข่งขันทุกคน (เก็บเฉพาะส่วนที่เปลี่ยน ไฟล์จึงเล็ก) รวมถึงตอนกดรันโค้ด คอมไพล์ไม่ผ่าน และส่งคำตอบ

เปิดจากหน้า 📊 สรุปผล → ปุ่ม "▶ Replay" ท้ายแถวของแต่ละคน

- เล่น/หยุด (Space), ทีละขั้น (← →), ลากแถบเวลา, ความเร็ว 1–60 เท่า
- "ข้ามช่วงที่ไม่ได้พิมพ์" ข้ามช่วงที่เงียบเกิน 3 วินาที
- แถบเวลามีจุดบอกเหตุการณ์: รันโค้ด / คอมไพล์ไม่ผ่าน / ส่ง ผ่านครบ / ส่ง ยังไม่ครบ / วางโค้ดก้อนใหญ่ คลิกจุดหรือรายการด้านขวาเพื่อกระโดดไปเวลานั้น
- สรุปตัวเลข: ผ่านครบเมื่อไร พิมพ์กี่ตัวอักษร วางโค้ดกี่ครั้ง รันและส่งกี่ครั้ง
- เลือก "ดูคนอื่น" เพื่อสลับไปดูผู้เข้าแข่งขันคนอื่นในรอบเดียวกัน

ใช้สอนวิธีคิดและการแก้ปัญหา (เช่น ฉายให้ดูว่าคนที่ทำได้เร็วเริ่มจากตรงไหน) หรือใช้ตรวจสอบความโปร่งใส

ไฟล์บันทึกอยู่ที่ `data/replays/<งานแข่ง>/r<รอบ>-p<ลำดับ>.json` บันทึกตอนจบรอบ ถ้าปิดเซิร์ฟเวอร์กลางรอบ รอบนั้นจะไม่มี Replay

### 🔍 ตรวจความคล้ายของโค้ด

ในหน้าสรุปผล แต่ละรอบมีปุ่ม "🔍 ตรวจความคล้ายของโค้ด" ระบบเทียบโค้ดสุดท้ายทุกคู่ที่ใช้ภาษาเดียวกัน

- **โครงสร้างเหมือน**: ไม่สนชื่อตัวแปร/ฟังก์ชัน จึงจับการลอกแล้วเปลี่ยนชื่อได้
- **เหมือนตรงตัว**: เทียบตามตัวอักษรจริง
- ไม่นับคอมเมนต์ และไม่นับส่วนที่มาจากโค้ดแม่แบบเริ่มต้น (ทุกคนเริ่มจากแม่แบบเดียวกัน)
- คู่ที่โครงสร้างเหมือนตั้งแต่ 80% ขึ้นไปเป็นแถบสีแดง 50–79% สีเหลือง
- ปุ่ม "เทียบโค้ด" เปิดโค้ดสองคนเคียงข้างกัน ไฮไลต์ส่วนที่ต่าง พร้อมลิงก์ไป Replay ของทั้งคู่
- ตารางผลแต่ละรอบมีคอลัมน์ "วางโค้ด" บอกจำนวนครั้งที่มีข้อความยาวเกิน 80 ตัวอักษรเข้ามาในครั้งเดียว

ข้อควรระวัง: ค่าความคล้ายสูงไม่ได้แปลว่าลอกเสมอ โจทย์ง่ายมักมีวิธีเขียนแบบเดียว และการวางโค้ดอาจมาจากการคัดลอกโค้ดของตัวเองหรือกด Undo ควรดู Replay ประกอบก่อนสรุป

## การอัปเดตความปลอดภัย

- อัปเดต **Node.js** บนเครื่องเซิร์ฟเวอร์เป็นรุ่นล่าสุดของสายที่ใช้อยู่เสมอ (ดูประกาศจาก nodejs.org หรือ ThaiCERT) แล้วรีสตาร์ตเซิร์ฟเวอร์ ไม่ต้องแก้โค้ดของระบบ
- ตรวจไลบรารีด้วย `npm audit` ถ้าพบช่องโหว่ แจ้งผู้พัฒนาให้อัปเดตเวอร์ชันใน package.json อย่าใช้ `npm audit fix --force`

## หมายเหตุสำคัญ

- **ความปลอดภัย:** v2 รันโค้ดใน Docker เป็นค่าเริ่มต้น ถ้าใช้ `EXECUTOR=local` โค้ดจะรันบนเครื่องเซิร์ฟเวอร์โดยตรงแบบ v1 ใช้เฉพาะกับผู้เล่นที่ไว้ใจได้
- C++ ที่ใช้ `ios::sync_with_stdio(false); cin.tie(0);` จะไม่ flush ข้อความก่อนรอ input อัตโนมัติ — ให้ใส่ `cout << flush` ถ้าต้องการให้ข้อความขึ้นก่อน
- โจทย์ คลังโจทย์ รายชื่อ รหัสเข้าใช้ และผลทุกรอบเก็บเป็นไฟล์ในโฟลเดอร์ `data` ส่วนโค้ดที่กำลังเขียนในรอบที่ยังไม่จบเก็บในหน่วยความจำ ถ้ารีสตาร์ตกลางรอบ ส่วนนี้จะหาย
- โฟลเดอร์ `data` มีเทสเคสลับและรหัสเข้าใช้ อย่าแชร์ให้ผู้เข้าแข่งขัน
- ฟอนต์โหลดจาก Google Fonts ถ้าไม่มีอินเทอร์เน็ตจะใช้ฟอนต์ของเครื่องแทน ส่วนอื่นใช้งานแบบออฟไลน์ได้ทั้งหมด
