# Code Duel

**ระบบประลองการเขียนโปรแกรมแบบเรียลไทม์ สำหรับห้องเรียน ค่าย และเวทีแข่งขัน**

> **Code Duel** is a self-hosted, real-time competitive programming arena for classrooms and coding events. Students solve the same problem simultaneously in Python or C++, submissions are judged automatically against hidden test cases inside isolated Docker containers, and the whole room can follow along on a live scoreboard. Runs fully offline on a local network from a single server. *(Documentation below is in Thai.)*

## ความสามารถหลัก

- **แข่งสดพร้อมกัน** รองรับ Python 3 และ C++20 (คอมไพล์ด้วย `-std=gnu++20` ปรับได้) ตัวเขียนโค้ดแบบ VS Code พร้อม console ที่พิมพ์ข้อมูลเข้าได้ระหว่างโปรแกรมทำงาน
- **ตรวจคำตอบอัตโนมัติ** ด้วยเทสเคสลับ บอกผลรายชุด (ผ่าน, คำตอบผิด, เกินเวลา, หน่วยความจำเกิน ฯลฯ) โดยไม่เปิดเผยข้อมูลในเทสเคส
- **รันโค้ดในคอนเทนเนอร์ Docker แยก** ไม่มีเครือข่าย จำกัด CPU, RAM และจำนวนโปรเซส
- **โจทย์เขียนด้วย Markdown** ใส่สูตรคณิตศาสตร์ได้ มีคลังโจทย์ไว้ใช้ซ้ำ
- **รหัสเข้าใช้รายคน** แข่งเป็นรอบ สรุปผลรวมทุกรอบ ส่งออก CSV และ PDF
- **จอผู้ชม** ตารางคะแนนสด ข่าวด่วน First Blood แช่แข็งตารางช่วงท้าย และประกาศผลแบบลุ้นทีละคน
- **เครื่องมือสำหรับครู** Replay ย้อนดูการพิมพ์โค้ด และตรวจความคล้ายของโค้ด
- **ใช้งานออฟไลน์ได้** ทั้งระบบทำงานในวงแลนจากเซิร์ฟเวอร์เครื่องเดียว เครื่องผู้เข้าแข่งขันใช้แค่เว็บเบราว์เซอร์

## ความต้องการของระบบ

**เครื่องเซิร์ฟเวอร์** (เครื่องของผู้ดูแล 1 เครื่อง)

| โปรแกรม | รุ่น |
|---|---|
| Node.js | รุ่น LTS ที่แก้ช่องโหว่แล้ว: **22.23.4+**, **24.22.1+** หรือ **26.12.1+** |
| Docker | Docker Desktop (macOS, Windows) หรือ Docker Engine (Linux) |

ไม่ต้องติดตั้ง Python หรือ g++ บนเครื่อง เพราะอยู่ใน image ของ Docker แล้ว

**เครื่องผู้เข้าแข่งขัน:** เว็บเบราว์เซอร์รุ่นใหม่ (Chrome, Edge, Firefox, Safari) จอกว้าง 1280px ขึ้นไปใช้งานสะดวกที่สุด

**เครือข่าย:** ทุกเครื่องอยู่วงแลนเดียวกัน และเครือข่ายต้องไม่บล็อกการเชื่อมต่อระหว่างเครื่อง (ดู [ใช้งานในวงแลน](#ใช้งานในวงแลน))

## ติดตั้ง

ทำครั้งแรกครั้งเดียว ต้องใช้อินเทอร์เน็ต เปิด Docker Desktop ไว้ก่อน

```bash
git clone https://github.com/<ชื่อผู้ใช้>/code-duel.git
cd code-duel
npm install
npm run build-runner      # สร้าง image สำหรับรันโค้ด (Python 3.12 + g++) ใช้เวลาสักครู่
npm run check             # ต้องขึ้น ✔ ทุกบรรทัด
```

เริ่มระบบทุกครั้งที่ใช้งาน (เปิด Docker Desktop ก่อน)

```bash
ADMIN_PASSWORD=รหัสของคุณ npm start
```

Terminal จะแสดงที่อยู่สำหรับเข้าใช้งาน

```
Code Duel v2.3.2 พร้อมใช้งาน
  ✔ Node.js 24.22.3 — แก้ช่องโหว่ตามประกาศ 21 ต.ค. 2569 แล้ว
  ที่รันโค้ด : Docker 27.x — image code-duel-runner:2
  C++       : -std=gnu++20
  เครื่องนี้ : http://localhost:3000/admin.html
  วงแลน (en0) : ผู้เล่นเข้า http://192.168.1.25:3000/player.html
```

| หน้า | ที่อยู่ | ใครใช้ |
|---|---|---|
| ผู้ดูแล | `/admin.html` | ครู / ผู้จัด (ต้องใช้รหัสผ่านผู้ดูแล) |
| ผู้เข้าแข่งขัน | `/player.html` | นักเรียน (ใช้รหัสเข้าใช้รายคน) |
| ตารางคะแนน | `/scoreboard.html` | ทุกคน |
| จอผู้ชม | `/spectator.html?key=…` | จอฉาย (ลิงก์อยู่ในหน้า admin) |
| สรุปผล | `/results.html` | ผู้ดูแล |

> **เปลี่ยนรหัสผ่านผู้ดูแลเสมอ** ค่าเริ่มต้นคือ `admin1234` ซึ่งใครที่เห็นโค้ดนี้ก็รู้

### อัปเดตจากเวอร์ชันเก่า

1. ดาวน์โหลดหรือ `git pull` เวอร์ชันใหม่
2. คัดลอกโฟลเดอร์ `data` จากของเดิมมาไว้ (คลังโจทย์ รายชื่อ และผลการแข่งอยู่ในนั้น)
3. `npm install` → `npm run build-runner` → `npm run check` → `npm start`

ดูสิ่งที่เปลี่ยนในแต่ละเวอร์ชันได้ที่ [CHANGELOG.md](CHANGELOG.md)

## ขั้นตอนการจัดแข่ง

1. **เตรียมผู้เข้าแข่งขัน** ในหน้า admin ใส่จำนวนคนที่ช่อง "ผู้เข้าแข่งขัน [ ] คน" กด "ปรับ" ระบบสร้างรหัสเข้าใช้ให้ทุกคน เปิดแผง "ผู้เข้าแข่งขันและรหัสเข้าใช้" เพื่อใส่ชื่อ (ไม่บังคับ) แล้วกด 🖨 พิมพ์บัตรรหัส
2. **ให้ผู้เข้าแข่งขันเข้าระบบ** เปิดที่อยู่ `/player.html` ที่แสดงในหน้า admin แล้วใส่รหัสจากบัตร
3. **เลือกโจทย์** จากคลังโจทย์ หรือเขียนใหม่ แล้วกด "เผยแพร่โจทย์" ผู้เข้าแข่งขันยังมองไม่เห็นโจทย์จนกว่าจะเริ่มรอบ
4. **เปิดจอผู้ชม** (ถ้ามี) จากแผง "จอผู้ชม" แล้วกด "🔇 เปิดเสียง" ที่จอนั้นหนึ่งครั้ง
5. **ตั้งเวลา แล้วกด "เริ่มรอบที่ N"** ทุกจอนับถอยหลัง 3-2-1 แล้วโจทย์เปิดพร้อมกัน
6. **ระหว่างแข่ง** ผู้ดูแลเห็นโค้ด console และอันดับสดของทุกคน กด "ดูเต็มจอ" เพื่อขยายจอของคนที่ต้องการ
7. **จบรอบ** (หมดเวลาหรือกด "จบรอบ") ถ้าตารางถูกแช่แข็ง ให้กด "▶ เปิดผลคนถัดไป" เพื่อประกาศผลทีละคน
8. **รอบถัดไป** กด "เตรียมรอบถัดไป" แล้ววนกลับไปข้อ 3
9. **จบงาน** เปิด "📊 สรุปผล" เพื่อดูอันดับรวม ดาวน์โหลด CSV หรือพิมพ์

## การเขียนโจทย์

โจทย์หนึ่งข้อคือไฟล์ Markdown หนึ่งไฟล์ เขียนในหน้า admin ซึ่งมีหน้าตัวอย่างของผู้เข้าแข่งขันแสดงอยู่ข้าง ๆ

| แท็ก | ผู้เข้าแข่งขันเห็นไหม | ใช้ทำอะไร |
|---|---|---|
| `# ชื่อโจทย์` | เห็น | หัวข้อแรกคือชื่อโจทย์ |
| `## ...` และข้อความทั่วไป | เห็น | คำอธิบาย ข้อมูลนำเข้า ข้อมูลส่งออก (ใช้ Markdown ได้เต็มที่) |
| `<example>` | เห็น | ตัวอย่าง พร้อมปุ่ม "รันตัวอย่างนี้" |
| `<test>` | **ไม่เห็น** | เทสเคสลับ ใช้ตรวจตอนส่งคำตอบ ใส่ได้หลายชุด |
| `<timelimit>2</timelimit>` | ไม่เห็น | เวลาสูงสุดต่อเทสเคส (วินาที) ค่าเริ่มต้น 2 |
| `<!-- ... -->` | ไม่เห็น | หมายเหตุสำหรับผู้ดูแล |

```markdown
# ผลรวมสองจำนวน

กำหนดจำนวนเต็ม $a$ และ $b$ ให้หาผลรวม

## ข้อมูลนำเข้า
บรรทัดเดียว มีจำนวนเต็ม $a$ และ $b$ โดย $-10^9 \le a, b \le 10^9$

## ข้อมูลส่งออก
ผลรวม $a + b$

## ตัวอย่าง
<example>
<input>
1 2
</input>
<output>
3
</output>
</example>

<timelimit>2</timelimit>

<test>
<input>
100 200
</input>
<output>
300
</output>
</test>
```

**สูตรคณิตศาสตร์** เขียนแบบ LaTeX (แสดงผลด้วย KaTeX แบบออฟไลน์)

| เขียน | ผลลัพธ์ |
|---|---|
| `$1 \le n \le 10^5$` | สูตรในบรรทัด |
| `$$\sum_{i=1}^{n} a_i$$` | สูตรแยกบรรทัด |
| `\$5` | เครื่องหมายดอลลาร์ธรรมดา |

ไม่แปลงสูตรในโค้ดและในกล่องตัวอย่าง ถ้าเขียนสูตรผิดจะแสดงเป็นตัวอักษรสีแดง หน้าไม่พัง

**กติกาการตรวจ**
- ไม่สนใจช่องว่างท้ายบรรทัดและบรรทัดว่างท้ายผลลัพธ์
- เทสเคสลับถูกตัดออกที่เซิร์ฟเวอร์ก่อนส่งให้ผู้เข้าแข่งขัน เปิดดูผ่านเบราว์เซอร์ไม่ได้
- ใน `<input>` และ `<output>` อย่าเว้นวรรคหน้าข้อมูล เพราะช่องว่างนำหน้าถือเป็นส่วนหนึ่งของคำตอบ

### คลังโจทย์

แผงด้านซ้ายของส่วนตั้งโจทย์ในหน้า admin: บันทึก, บันทึกเป็นโจทย์ใหม่, เปิดแก้ไข, ค้นหา, ลบ, นำเข้าไฟล์ `.md` ได้หลายไฟล์พร้อมกัน และดาวน์โหลดเป็น `.md` โจทย์ที่กำลังใช้มีป้าย "กำลังใช้" ครั้งแรกที่เปิดระบบจะมีโจทย์ตัวอย่างให้หนึ่งข้อ

## ฝั่งผู้เข้าแข่งขัน

**เข้าระบบ:** เปิด `/player.html` ใส่รหัส 6 ตัวจากบัตร (เช่น `K7P-3MX`) ครั้งแรกอาจต้องใส่ชื่อ ถ้าหลุดก็กลับเข้าด้วยรหัสเดิมได้ โค้ดที่เขียนไว้ไม่หาย รหัสหนึ่งใช้ได้ทีละเครื่อง ใส่ผิด 5 ครั้งติดกันต้องรอ 1 นาที

**หน้าจอ:** โจทย์ (ซ้าย) ตัวเขียนโค้ด (ขวาบน) และ console (ขวาล่าง)
- ⌘/Ctrl + B ซ่อนหรือแสดงโจทย์ ทุกส่วนมีปุ่มยุบและขยาย และลากเส้นแบ่งเพื่อปรับขนาดได้ เบราว์เซอร์จำการจัดหน้าจอไว้
- **รันโค้ด** (Ctrl+Enter) ทดสอบกับตัวอย่างหรือข้อมูลที่พิมพ์เอง ไม่นับคะแนน
- **ส่งคำตอบ** (Ctrl+Shift+Enter) ตรวจกับเทสเคสลับ นับคะแนน ส่งกี่ครั้งก็ได้
- 📊 ตารางคะแนน และปุ่ม 🔊/🔇 เปิดปิดเสียง อยู่ที่แถบด้านบน

**ผลการตรวจ**

| ระบบบอกว่า | แปลว่า |
|---|---|
| ผ่าน | ถูกต้องและทันเวลา |
| คำตอบผิด | ผลไม่ตรงกับคำตอบของเทสเคส |
| เกินเวลา | ทำงานนานเกิน `<timelimit>` |
| หน่วยความจำเกิน | ใช้ RAM เกินที่กำหนด |
| รันไม่สำเร็จ | โปรแกรม error ระหว่างทำงาน |
| ผลลัพธ์ยาวเกินไป | พิมพ์ผลลัพธ์ออกมามากผิดปกติ |
| คอมไพล์ไม่ผ่าน | โค้ด C++ ผิดไวยากรณ์ (ดูข้อความใน console) |

**C++:** คอมไพล์ด้วย `g++ -std=gnu++20 -O2` เป็นค่าเริ่มต้น ใช้ฟีเจอร์ C++20 (concepts, ranges, `<=>`, designated initializers) และส่วนขยายของ GNU (`__int128`, `<bits/stdc++.h>`) ได้ ใน Docker image เป็น g++ 12 ซึ่งยังไม่มี `std::format` ตั้งมาตรฐานอื่นได้ด้วย `CXX_STD` ชื่อภาษาในหน้าจอจะเปลี่ยนตามให้เอง

## รอบการแข่งและสรุปผล

- ปุ่มในหน้า admin: **"เริ่มรอบที่ N"**, **"จบรอบ"**, **"เตรียมรอบถัดไป"**
- จบรอบแล้วระบบบันทึกผลทันที ผู้เข้าแข่งขันเห็นหน้าต่างสรุปผลรอบพร้อมอันดับของตัวเอง
- **อันดับในแต่ละรอบ:** ผ่านเทสเคสมากกว่า → ทำได้เร็วกว่า (นับจากเริ่มรอบ) → ส่งน้อยครั้งกว่า
- **คะแนนรอบ** = ร้อยละของเทสเคสที่ผ่าน (ผ่านครบ = 100) ส่งผิดไม่หักคะแนน
- **อันดับรวม** = ผลรวมคะแนนทุกรอบ ถ้าเท่ากันดูเวลารวมที่น้อยกว่า
- การเผยแพร่โจทย์ใหม่ การเริ่มรอบ และการเตรียมรอบถัดไป จะล้างคะแนนรอบปัจจุบัน (ผลรอบที่จบแล้วยังอยู่)

**หน้าสรุปผล** (ปุ่ม 📊 สรุปผล): อันดับรวมทุกรอบ ผลแต่ละรอบพร้อมโค้ดสุดท้ายของแต่ละคน โหมดนำเสนอสำหรับฉาย ดาวน์โหลด CSV (ผลรวม / รายละเอียด, เปิดใน Excel แล้วภาษาไทยไม่เพี้ยน) พิมพ์หรือบันทึก PDF ลบรอบทดสอบ และ "เริ่มงานแข่งใหม่" ซึ่งเก็บงานเดิมไว้ใน `data/events/`

| ใครดู | ทุกคน รวมถึงมือถือผู้ชม | จอฉาย ห้องผู้ชม การถ่ายทอดสด |
| เนื้อหา | อันดับสด ข่าวด่วน First Blood นับถอยหลัง | ทุกอย่างทางซ้าย + จอโค้ด 4 อันดับแรก หรือ Spotlight คนเดียว |
| โค้ด | ไม่มี | ซ่อน / หน่วงเวลา / สด ตามที่ตั้ง |
| เข้าถึง | ไม่ต้องใช้รหัส | ต้องมีคีย์ในลิงก์ |

**การตั้งค่า**
- **โค้ดบนจอผู้ชม:** *ซ่อนระหว่างแข่ง* (ค่าเริ่มต้น ใช้เมื่อจอฉายอยู่ห้องเดียวกับผู้เข้าแข่งขัน) / *หน่วงเวลา N นาที* / *สด* (ผู้ชมอยู่คนละห้อง)
- **แช่แข็งตาราง N นาทีสุดท้าย** (ค่าเริ่มต้น 10, ใส่ 0 = ไม่แช่แข็ง) การส่งหลังแช่แข็งแสดงเป็น `+N?`
- **นับถอยหลัง 3-2-1** ก่อนเปิดโจทย์
- **Spotlight** เลือกคนเดียวขึ้นเต็มจอ หรือกด 🎥 บนการ์ดของคนนั้น
- **สร้างคีย์ใหม่** ลิงก์จอผู้ชมเดิมใช้ไม่ได้ทันที

**ประกาศผลแบบลุ้น:** ถ้าตารางถูกแช่แข็งตอนจบรอบ ผู้เข้าแข่งขันเห็นแค่ผลของตัวเอง ผู้ดูแลกด "▶ เปิดผลคนถัดไป" เพื่อเปิดผลทีละคนจากอันดับล่างขึ้นบน เปิดครบแล้วป้าย 🏆 ขึ้นจอ และทุกคนเห็นอันดับเต็ม

เสียงสร้างในเบราว์เซอร์ ไม่ต้องมีไฟล์ จอผู้ชมต้องกด "🔇 เปิดเสียง" หนึ่งครั้งตามข้อกำหนดของเบราว์เซอร์

## เครื่องมือสำหรับครู

### ▶ Replay ย้อนดูการพิมพ์โค้ด

ระบบบันทึกทุกการแก้ไขโค้ดของทุกคนตลอดรอบ เปิดได้จากปุ่ม "▶ Replay" ในหน้าสรุปผล
- เล่นหรือหยุด (Space), ทีละขั้น (← →), ลากแถบเวลา, ความเร็ว 1–60 เท่า, ข้ามช่วงที่ไม่ได้พิมพ์
- แถบเวลามีจุดบอกเหตุการณ์: รันโค้ด, คอมไพล์ไม่ผ่าน, ส่งคำตอบ, วางโค้ดก้อนใหญ่
- สลับดูผู้เข้าแข่งขันคนอื่นในรอบเดียวกันได้

บันทึกตอนจบรอบที่ `data/replays/` ถ้าปิดเซิร์ฟเวอร์กลางรอบ รอบนั้นจะไม่มี Replay

### 🔍 ตรวจความคล้ายของโค้ด

ปุ่มในแต่ละรอบของหน้าสรุปผล เทียบโค้ดสุดท้ายทุกคู่ที่ใช้ภาษาเดียวกัน
- **โครงสร้างเหมือน** ไม่สนชื่อตัวแปร จึงจับการลอกแล้วเปลี่ยนชื่อได้ / **เหมือนตรงตัว** เทียบตามตัวอักษร
- ไม่นับคอมเมนต์และโค้ดแม่แบบเริ่มต้น คู่ที่ ≥80% เป็นสีแดง 50–79% สีเหลือง
- "เทียบโค้ด" เปิดโค้ดสองคนเคียงข้างกัน พร้อมลิงก์ไป Replay ของทั้งคู่

> ค่าความคล้ายสูงไม่ได้แปลว่าลอกเสมอ โจทย์ง่ายมักเขียนออกมาแบบเดียวกัน ควรดู Replay ประกอบก่อนสรุป

## ความปลอดภัย

### รันโค้ดในคอนเทนเนอร์แยก

ทุกครั้งที่รันหรือส่งคำตอบ ระบบสร้างคอนเทนเนอร์ใหม่ แล้วลบทิ้งทันทีเมื่อเสร็จ

| ข้อจำกัด | ป้องกันอะไร |
|---|---|
| ไม่มีเครือข่าย (`--network none`) | ออกอินเทอร์เน็ต หรือเจาะเครื่องอื่นในวงแลน |
| มองไม่เห็นไฟล์ของเซิร์ฟเวอร์ | อ่านเทสเคสลับหรือรหัสเข้าใช้ |
| ระบบไฟล์อ่านอย่างเดียว เขียนได้เฉพาะ `/work` และ `/tmp` ขนาดจำกัด | เขียนไฟล์จนดิสก์เต็ม |
| RAM 256 MB, CPU 1 ตัว, 64 โปรเซส | กินทรัพยากรจนเครื่องค้าง, fork bomb |
| ไม่ใช่ root, `--cap-drop ALL`, `no-new-privileges` | หลุดออกจากคอนเทนเนอร์ |
| `timeout` ในคอนเทนเนอร์ และหมดอายุเองใน 30 นาที | โปรเซสค้าง แม้เซิร์ฟเวอร์ล่ม |

Docker ลดความเสี่ยงได้มากแต่ไม่ใช่การป้องกันสมบูรณ์ ถ้าเปิดให้คนทั่วไปเข้าผ่านอินเทอร์เน็ต ควรใช้เครื่องที่ไม่มีข้อมูลสำคัญ และพิจารณา gVisor (`--runtime runsc`) หรือ VM แยก

### ตรวจรุ่น Node.js อัตโนมัติ

ระบบไม่ยอมเริ่มบน Node.js ที่มีช่องโหว่ตามประกาศความปลอดภัย (ตาราง `MIN_SAFE` ใน `node-check.js`)

| รุ่นที่ใช้ | ผล |
|---|---|
| 22.23.4+, 24.22.1+, 26.12.1+ | ✔ เริ่มได้ |
| ต่ำกว่านั้นในสายเดียวกัน, 23.x, 25.x, ต่ำกว่า 22 | ✖ ไม่ยอมเริ่ม และบอกรุ่นที่ต้องอัปเดต |
| ใหม่กว่าตาราง | ✔ เริ่มได้ พร้อมเตือนให้ตรวจประกาศล่าสุด |

เมื่อมีประกาศช่องโหว่ใหม่ แก้ `MIN_SAFE` ใน `node-check.js` ที่เดียว กรณีจำเป็นจริง ๆ รันชั่วคราวได้ด้วย `ALLOW_INSECURE_NODE=1 npm start` (หน้า admin จะมีแถบเตือนสีแดง)

### ไลบรารีและ image

- รุ่นไลบรารีตรึงแบบตรงตัว และ `package-lock.json` เก็บ hash ของทุกแพ็กเกจ (อย่าลบไฟล์นี้)
- ไลบรารีย่อยที่ออกใหม่ไม่ถึง 14 วัน ถูกตรึงไว้ที่รุ่นก่อนหน้าใน `overrides` ของ `package.json`
- `npm run security` ตรวจรุ่น Node.js และช่องโหว่ของไลบรารีในคำสั่งเดียว อย่าใช้ `npm audit fix --force`
- `npm run build-runner` ดึง image ฐานล่าสุดและแพตช์ของ Debian ทุกครั้ง ควรรันใหม่ทุกต้นภาคเรียน

### โฟลเดอร์ data

เก็บเทสเคสลับ รหัสเข้าใช้ คีย์จอผู้ชม และผลการแข่ง **อย่าแชร์ให้ผู้เข้าแข่งขัน และอย่าอัปโหลดขึ้น GitHub** (`.gitignore` กันไว้แล้ว แต่การลากไฟล์ขึ้นหน้าเว็บ GitHub ไม่ผ่าน `.gitignore`) สำรองข้อมูลได้ด้วยการคัดลอกทั้งโฟลเดอร์

## ใช้งานในวงแลน

ให้ผู้เข้าแข่งขันเปิดที่อยู่ที่ Terminal หรือหน้า admin แสดง เช่น `http://192.168.1.25:3000/player.html` **ห้ามใช้ `localhost` บนเครื่องผู้เข้าแข่งขัน** ไลบรารีทั้งหมดให้บริการจากเซิร์ฟเวอร์เอง จึงใช้ได้โดยไม่มีอินเทอร์เน็ต (ฟอนต์จะเปลี่ยนเป็นฟอนต์ของเครื่องแทน)

**ถ้าเครื่องอื่นเข้าไม่ได้ ตรวจตามลำดับ**

1. **เซิร์ฟเวอร์เปิดผ่าน IP ได้ไหม:** บนเครื่องเซิร์ฟเวอร์รัน `curl -I http://<IP>:3000/player.html` ต้องได้ `200 OK`
2. **ไฟร์วอลล์**
   - macOS: System Settings → Network → Firewall → อนุญาต `node`
   - macOS 15 ขึ้นไป: System Settings → Privacy & Security → **Local Network** → เปิดให้ Terminal (เครื่องเซิร์ฟเวอร์) และเบราว์เซอร์ (เครื่องผู้เข้าแข่งขัน)
   - Windows: PowerShell (Run as administrator) `New-NetFirewallRule -DisplayName "Code Duel" -Direction Inbound -Protocol TCP -LocalPort 3000 -Action Allow -Profile Any` และตั้งเครือข่ายเป็น Private
   - Linux: `sudo ufw allow 3000/tcp`
3. **วงเดียวกันไหม:** IP ของเครื่องผู้เข้าแข่งขันควรขึ้นต้นเหมือนเซิร์ฟเวอร์ ทดสอบด้วย `nc -vz <IP> 3000` (Mac) หรือ `Test-NetConnection <IP> -Port 3000` (Windows)
4. **Wi-Fi บล็อกเครื่องคุยกันเอง:** Wi-Fi ของโรงแรม Wi-Fi สำหรับแขก และ Wi-Fi องค์กรหลายแห่งเปิด Client Isolation ไว้ ใช้เราเตอร์พกพาของตัวเอง (ไม่ต้องต่ออินเทอร์เน็ต) หรือ Personal Hotspot จากมือถือ
5. **มีหลาย IP:** ถ้ามี VPN หรือ Docker ให้ใช้ IP ของการ์ด Wi-Fi/Ethernet (`en0` บน Mac)
6. **WSL2 บน Windows:** รัน Node.js บน Windows โดยตรง หรือตั้ง `netsh interface portproxy` ไปยัง IP ของ WSL
